# b1.11 — the OAuth2 boundary holds

Closes audit findings **H-05** and **H-06** (block B1.11 of
`docs/plans/b1-delivery-roadmap.md`).

## What an operator sees

- An identity provider's error body no longer travels to agents. When the
  token endpoint refuses the broker's request, the error names the status
  and the RFC 6749 error code — `invalid_client`, `temporarily_unavailable`
  — and states that the provider's body was not relayed. A hostile or
  misconfigured IdP that reflects the client credential into its
  `error_description` (or into the `error` field itself) has no route to
  the agent through an error message: `asv oauth2 whoami` fails cleanly
  with exit 1, in prose and in `--json`.
- Refresh tokens survive a single form encoding. Tokens containing `+`,
  `%`, `&` or `=` used to be double-encoded (`a+b` → `a%252Bb`), so the
  provider saw a different token and answered `invalid_grant` — a working
  refresh silently broken. The wire now carries exactly one encoding.
- `asv status` and the wire protocol are unchanged by this block.

## Why

The audit measured both channels live: up to 200 characters of
provider-controlled text reached the CLI's stderr through the token
endpoint's error path, and the refresh grant's encoding bug broke the
rotation for any token with an escapable character. The fix is one rule —
`provider_errors` — applied to every provider-facing surface: broker-chosen
fields only, never a stranger's text. The same rule the resource-server
path always followed, now stated and shared in one place.
