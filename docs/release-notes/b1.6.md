# B1.6 — rustfmt version pin policy

B1.6 stops the kind of silent rustfmt drift that B1.5 paid
on `b1/worker-lifetime`. The drift was between rustfmt 1.5
(written by the original code) and rustfmt 1.9.0 (the
dev host's toolchain at the time of B1.5). B1.6 makes
that class of drift structurally impossible by pinning the
workspace's toolchain to a specific stable.

## What B1.6 ships

- `rust-toolchain.toml` (4 lines) at the workspace root.
  Pins `channel = "1.97.1"` with
  `components = ["rustfmt", "clippy", "rust-analyzer"]`
  and `profile = "minimal"`.
- `docs/policies/rustfmt-pin-policy.md` (138 lines): the
  policy. States the rule, the bump cadence, the MSRV/pin
  relationship, and the "what is NOT in this policy"
  section.
- `scripts/check-rustfmt-pin.sh` (96 lines): the
  verification script. Exit 0/1/2/3/4 by failure mode.

Total: 238 lines, **0 lines of code change**.

## Why `1.97.1`

Candidates considered:

| Version | Status | Decision |
|---|---|---|
| `1.95.0` | deno's pin; not installed locally | rejected (would force 30-60s download) |
| `1.97.1` | installed locally; 1 minor behind bleeding edge | **chosen** |
| `1.98.1` | dev host toolchain | rejected (would re-introduce B1.5 problem) |
| `1.99.0` | active stable on dev | rejected (same) |

`1.97.1` is the most recent stable that is **not** the
dev host's bleeding edge, so the codebase is anchored to
a baseline one minor behind the host. The "1 minor
behind" framing is what the user-facing policy relies
on: the codebase is the source of truth, the dev's
machine follows it.

## What B1.6 does NOT include

- No bump of MSRV. `rust-version = "1.85"` is the consumer
  signal, untouched.
- No nightly pin. The project is stable.
- No `rustfmt.toml` config. The pin is sufficient.
- No CI changes. The local SDDK gate does not run
  `cargo fmt`; hosted CI does not exist yet.
- No automated bump. Manual review at every workspace
  version bump.
- No SDDK pre-merge-commit edit. Out of scope for this
  repo; the script is invocable manually.

## Migration

No migration required. B1.6 is a housekeeping release:
no feature change, no API change, no behavior change. The
only user-visible effect is that contributors and CI will
use rustc 1.97.1 (rustup activates it automatically on
`cd` into the repo, if installed; otherwise
`rustup toolchain install 1.97.1` is required).
