# B1.9 — sessions die with their process

B1.9 closes audit finding H-03. A session record used to keep the
connection-time boolean and compare PIDs as integers: a process that died
left its session ownable by whoever recycled the PID next — the exact
ambiguity ADR-0003's pidfd exists to close, reopened one layer above the
connection.

## What B1.9 ships

- The session record owns a duplicate of the connection's pidfd, so
  ownership and pin evidence are answered against the live process, and
  the UAT-030 "pins release when the session ends" property is structural
  (the handle dies with the record).
- One `owns()` answers every session-scoped verb: PID equality AND the
  pinned process still alive, decided by the kernel (`poll` on the pidfd),
  fail-closed when the poll itself cannot run.
- Surrogate minting and isolated execution gate on live evidence, not on
  what was true when the session opened.
- A pinned peer whose pin cannot be duplicated is refused at session
  creation instead of silently downgraded. Unpinned sessions keep the
  documented weaker PID-only ownership.

No wire change: the same requests, the same refusal texts an agent already
speaks.

## Falsification

The unit row observed RED before the change — a fresh identity claiming the
dead owner's PID was `belongs_to` and `is_pinned` both true — and GREEN
after. The ephemeral real-process check drove a real brokerd: a third-PID
helper was pinned through real SO_PEERCRED and minted a surrogate through
its live pin; once the helper exited, the session refused a mint with the
ownership message and the broker stayed healthy. That check retires with
the block; the unit suite is the permanent half.
