## Summary

`b1.4` ships the operator-facing wire for the runtime-aware
posture that B1.3 (cgroup-probe + `degraded_reason`)
introduced. A new CLI flag, `--runtime-posture-aware`, lets
the operator opt in to having the audit row reflect the
actual host posture. Without the flag, the audit row keeps
the B1.1 honest label (`IsOLATED_PROCESS_EXPOSURE` +
`degraded_reason: None`).

This is the first release where the broker's audit chain
can carry `STRONG_SECRETLESS` rows in production. The
posture flip is explicit, audited, and operator-controlled.

## What lands in this release

### New operator-facing surface

- **`--runtime-posture-aware`** CLI flag on the broker.
  Absent by default. With the flag, the audit row reflects
  the runtime decision; without the flag, the B1.1 honest
  label is preserved.
- **`--harden`** is **independent** of `--runtime-posture-aware`.
  A deployment that wants the cgroup fence without the
  audited posture (or vice versa) can ask for either.

### Library changes

- **`effective_posture_for_audit(harden, opt_in) -> (PostureLabel, Option<DegradedReason>)`**
  in `crates/broker/src/isolated_exec.rs`. The single point
  of policy that the audit row consults. The 2x2 truth
  table:
  - `(None, _)` → `(PostureLabel::default(), None)` — no harden profile
  - `(Some(_), false)` → `(PostureLabel::default(), None)` — opt-out
  - `(Some(h), true)` → `effective_posture(h)` — opt-in, reflect runtime

- **`BrokerState`** in `crates/broker/src/lib.rs` gained
  `pub harden_config: Option<HardenConfig>` and
  `pub runtime_posture_aware: bool` (both default to
  `None` / `false`).

- **`worker::spawn` and `audit_worker`** in
  `crates/broker/src/worker.rs` take the new parameters
  end-to-end. `audit_worker` is now 9 arguments
  (`#[allow(clippy::too_many_arguments)]` widened from 8 to 9).
  8 internal call sites and 1 production call site (in
  `lib.rs:2223`) updated.

### IPC DTO

## Upgrade / migration notes

There is no migration. The new flag is opt-in. Existing
deployments that do not pass `--runtime-posture-aware` see
no change in the audit row format. Existing lockfiles that
pin the broker workspace version see no change.

The IPC DTO did not change. Existing audit-log consumers
do not need to update.

## Known limitations

- The `--runtime-posture-aware` flag is a deployment-time
  switch, not a per-worker switch. A single broker process
  flips the audit row for every worker it spawns. A future
  release may add per-worker posture; the current design
  intentionally does not.
- The flag does not change the runtime behavior of the
  worker — only the audit row. A deployment that wants the
  cgroup fence must also pass `--harden`; the two are
  independent by design (see above).
- The `IsolatedProcessExposure` + `degraded_reason`
  combination is cfg-gated between Linux and non-Linux
  hosts. A non-Linux host that opts in will see
  `IsolatedProcessExposure` + `degraded_reason:
  "NonLinux"`. A Linux host without cgroup v2 mounted will
  see `IsolatedProcessExposure` + `degraded_reason:
  "CgroupV2Unavailable"`.
