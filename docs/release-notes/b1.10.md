# B1.10 — the recovery journal is real

B1.10 closes audit finding H-04. The recovery module existed since M13 with
a normative UAT and zero production callers, while the dist profile comment
and the systemd unit both claimed a fsync'd journal was already protecting
vault mutations. The spec had already decided: UAT-035 is M13's exit UAT, so
the module was wired, not retired.

## What B1.10 ships

- Every vault mutation journals its intent (kind + credential id, never
  secret material) and fsyncs it BEFORE the write; the intent is cleared the
  moment the write returns, either way. A surviving entry therefore means
  exactly one thing: the mutation was in flight when the process died.
- brokerd reconciles surviving intents at startup against the loaded
  inventory and reports each in operator language — including the
  security-relevant case of a revocation that did not land ("the vault STILL
  holds it — re-issue the revocation"). The journal restarts empty after
  reconciliation; torn and corrupt records stop the replay per UAT-035's own
  discipline, and the vault — atomic — stays the source of truth.
- `asv status` reports the reconciled count on the wire and in words.
- The journal lives beside the vault by default; `--journal-file` overrides.
- The two comments that claimed the journal existed now describe the journal
  that exists.

## Falsification

The ephemeral real-process check seeds the journal with the bytes a killed
process would have left and requires the reconciliation on the wire (count
2), in the broker's own log (both intents named for an operator), and in the
file (restarted empty); then a real mutation attempt, a SIGKILL, and a
restart prove clean mutations leave zero intents. With the startup
reconciliation disabled, the check goes red; restored, green. It retires
with the block; the unit rows and UAT-035's module suite are the permanent
half.
